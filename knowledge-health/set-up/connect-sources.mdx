Choose the tools Knowledge Health audits.

Knowledge Health works best when your docs are in Falconer, but it also audits docs where they already live. It reads the context across all your connected tools, works out which sources are accurate, and flags issues after checking each source against the others.

To connect a source, open **Settings** and choose **Integrations**. For how integrations work in general, see [Connect sources](/set-up/connect-sources).

## What each source includes

| Source | What it adds |
| --- | --- |
| **Public docs** | Your documentation site, added by URL on the **Public docs** card. Knowledge Health crawls the site and checks its pages against each other and against your code (if connected). |
| [**GitHub**](/integrations/github) | Repositories, code files, and pull requests. Knowledge Health checks doc claims against the code and flags drift after a pull request merges. It reads repositories and never writes to them. |
| [**Bitbucket**](/integrations/bitbucket) | Repositories and merged pull requests. Knowledge Health checks doc claims against the code, the same way it does for GitHub. |
| [**Notion**](/integrations/notion) | Pages and databases you share with Falconer. |
| [**Confluence**](/integrations/confluence) | Pages from the spaces you select. |
| [**Google Drive**](/integrations/google-drive) | Docs, sheets, and slides from the drives you connect. |
| [**Google Workspace**](/integrations/google-workspace) | Documents across your Google Workspace, connected for the whole organization. |
| [**Slab**](/integrations/slab) | Posts from your Slab knowledge base. |
| [**Slack**](/integrations/slack) | Conversations Knowledge Health uses to find coverage gaps. |
| [**Linear**](/integrations/linear) | Issues that record decisions and known problems. |
| [**Granola**](/integrations/granola) | Meeting notes that record what people discussed and decided. |
| [**Jira**](/integrations/jira) | Issues that record decisions and known problems, checked along with Linear and GitHub issues. |
| [**Asana**](/integrations/asana) | Tasks that record decisions and known problems, checked along with Linear and GitHub issues. |
| [**Zendesk**](/integrations/zendesk) | Help center articles, checked against your other docs and your code. |
| **Intercom** | Help center articles, checked against your other docs and your code. |

Start with your docs and your code, then add wikis and conversations.

Knowledge Health can run once your first source finishes syncing. Until then, the page shows **Syncing your data** and updates when the sync is done. If you already have past scans, the run banner shows **Syncing your sources** and **Run now is available once the sync finishes**.

## Audit docs stored in a repository

Connect the repository and choose the folder that holds your docs. Knowledge Health treats that folder as your docs and the rest of the repository as code to check them against.

## Change sources later

To add a source, connect it in **Integrations**. To remove one, disconnect it there. To narrow one, click **Configure** on its card and limit the repositories, folders, spaces, or channels Falconer can read.

The next scan picks up the change once indexing finishes. To audit right away, click **Run now**.

## FAQ

<AccordionGroup>

<Accordion title="My help center isn't a native integration. Can Knowledge Health still audit it?">

Yes. Add the public help center URL on the **Public docs** card, and Knowledge Health crawls it like any docs site.

</Accordion>

<Accordion title="Does Knowledge Health read Asana, Jira, Zendesk, Gmail, or databases?">

Partly. Knowledge Health reads Zendesk and Intercom help center articles, and it checks issues in Jira and Asana along with Linear and GitHub. Gmail and databases aren’t audited yet. You can still connect them for search and Falcon.

</Accordion>

</AccordionGroup>
